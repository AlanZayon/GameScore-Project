# Design Principles

## 1. Design Is Communication

Every visual decision communicates importance.

Size, position, contrast, spacing, typography, color, and motion should reinforce hierarchy.

If everything is emphasized, nothing is emphasized.

---

## 2. Prefer Hierarchy Over Decoration

When an interface feels weak, first investigate:

* hierarchy
* spacing
* typography
* grouping
* alignment
* contrast

before adding:

* gradients
* shadows
* animations
* illustrations
* decorative backgrounds

---

## 3. Use Contrast Intentionally

Contrast can come from:

* size
* weight
* color
* position
* density
* whitespace
* shape

Do not rely only on color.

---

## 4. Consistency Creates Trust

Repeated patterns should behave consistently.

If two components represent the same conceptual action, their:

* appearance
* interaction
* spacing
* feedback

should usually be consistent.

---

## 5. Break Consistency Deliberately

Consistency is not absolute.

Break established patterns when doing so improves:

* hierarchy
* usability
* discoverability
* emphasis
* product identity

The deviation should be intentional.

---

## 6. Reduce Cognitive Load

Prefer:

```text
fewer decisions
clearer hierarchy
predictable interaction
progressive disclosure
meaningful defaults
```

Avoid:

```text
unnecessary controls
duplicate information
ambiguous labels
decorative complexity
```

---

## 7. Content Comes First

Do not design the interface around empty placeholders.

Understand the actual content.

Consider:

* long titles
* short titles
* missing images
* large numbers
* multilingual text
* empty states
* errors

The interface should survive realistic content.

---

## 8. Design for Failure

A mature interface includes:

```text
loading
empty
error
permission denied
offline
partial data
slow network
```

Failure states are part of the product.

---

## 9. Mobile Is a First-Class Experience

Do not treat mobile as:

```text
desktop × smaller
```

Instead determine whether:

```text
navigation
interaction
content order
density
actions
components
```

should change.

---

## 10. Avoid Visual Noise

If removing an element does not reduce usability or understanding, question whether it is necessary.

---

## 11. Distinctiveness Should Come From the System

A distinctive interface does not require visual gimmicks.

Distinctiveness can come from:

* typography
* composition
* information architecture
* interaction patterns
* illustration style
* iconography
* content presentation
* spacing rhythm
* motion language

---

## 12. AI-Slop Detection

Before finalizing an interface, ask:

* Would this design look interchangeable with thousands of AI-generated websites?
* Are gradients being used without purpose?
* Are cards being used merely because cards are easy to generate?
* Are there too many pills?
* Are there too many shadows?
* Are icons replacing meaningful labels?
* Is there an unnecessary dashboard aesthetic?
* Is every section enclosed in a rounded container?
* Is the design relying on visual decoration instead of hierarchy?

If yes, simplify or establish a stronger visual identity.
